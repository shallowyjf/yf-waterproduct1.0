## 从 Git 仓库启动

本仓库根目录即原型网站目录，包含产品 1.0、2.0 与学校专供入口。当前是 HTML/CSS/JavaScript 静态原型，React 与服务端开发尚未实施。

```powershell
git clone https://github.com/shallowyjf/yf-waterproduct1.0.git
cd yf-waterproduct1.0
python -m http.server 8765 --bind 127.0.0.1
```

打开 http://127.0.0.1:8765/index.html 。Python 仅用于静态文件服务，也可将本目录部署到 Nginx 或 IIS，无需安装前端依赖或数据库。

| --- | --- | --- |

这些是公开的原型演示凭据，采用前端功能限制，不是服务端身份认证。学校账号默认进入上海学校项目。浏览器本地保存的修改不会同步给其他访问者，真实部署需要服务端权限和数据服务。

安装 Node.js 22 或更新版本后，可执行 `npm test` 运行逻辑测试，不需要 `npm install`。`tools/` 中的数据重建、截图和浏览器验收脚本是辅助工具，部分需要完整工作区源数据、Python 库或 Playwright；直接查看网页不需要运行它们。

仓库保留内置数据集和第三方运行库；运行日志、截图、临时报表和本地依赖由 `.gitignore` 排除。下文提及的完整产品设计资料另行保存在产品工作区，不随本次原型代码同步。

## 上海技术学院项目（2026-10-27）

现用拓扑来自 `data/sources/campus_water_completed1026_管长_铸铁DN200.net`，实际包含96个节点、94条管线、2个连通分量，总管长1905.820928635 m。源NET没有水源元素；原始标题/备注仍写102点100管，导入以实际元素为准，不把旧版水源建模带入最新版。节点编号、连接、管长、管径、坐标、描述和标签逐项保留。

源描述共有10条二级表标注：9个节点及管段40，其中JS643为北侧入口开挖标注、JS258为北侧入口开挖待选位置；两条标注不代表需同时安装两套设备。管段40的标注保留在管上，其具体段内安装点待确认。资产地图和拓扑详情显示完整源描述及安装标注，可按“二级表”“开挖”搜索。`metadata.installationPoints`保存结构化标注，`selectionPending`区分待选位置，不创建真实设备、读数或已安装状态。

当前采用用户于2026-10-27指定的四个DMA分区：

| 分区 | 范围 | 自有节点 | 管段 | 管长（m） |
| --- | --- | ---: | ---: | ---: |
| DMA-01 | 节点28之后，含垃圾房、体育馆厕所1/2，至花房 | 13 | 12 | 577.775 |
| DMA-02 | JS258之后，含北教学楼与宿舍1/2/3 | 28 | 27 | 318.182 |
| DMA-03 | 南侧入口JS52-1起，含南教学楼、食堂及幼儿园，至节点1 | 30 | 29 | 633.330 |
| DMA-04 | 节点1经管34，至宿舍4/5/6 | 21 | 21 | 329.079 |

节点1是DMA-03/04的共用交界点，仅计入DMA-03成员；DMA-04管段几何仍包含该入口端点。幼儿园管32/33归DMA-03，管34归DMA-04。北侧公共入口保留4个未分配节点（JS641/642/643/644）和5条管线（L003/004/005/L007/40），未强行并入节点28或JS258下游的分区。每个节点和管段至多归一个DMA，4区加公共范围覆盖完整最新拓扑。

用户所称分区3的“水源2”已确认指南侧JS52-1；该称谓用于分区起点，源NET的节点类型保持不变。分区边界按10m管线走廊绘制，共用节点附近裁切交叠区域，不改变任何原始管线连接；现场计量与监测尚未接入。

旧拓扑和五分区归档于 `data/archives/campus-before-20261026/`。浏览器首次替换旧拓扑前完整备份旧快照、目录、设备及运行记录，并建立可查看的更新前拓扑版本；旧挂接留在归档版本。此次四DMA方案单独升级并保留之前的方案，不覆盖现有节点管线及设备档案。

浏览器备份先事务提交至同站点 IndexedDB `water-campus-archives-v1`，localStorage中的归档快照仅存备份引用，避免旧站点空间已满导致重复存储失败。页面启动先预载归档；备份失败时保留原数据并显示可重试提示。迁移后的普通查看、历史版本切换和导出均通过统一快照读取解析引用。清理站点存储仍会删除浏览器侧数据，重要归档请使用系统拓扑导出保存文件。

可移植快照为 `data/campus-topology.json`；重建命令为 `python tools/import-campus-net.py --source data/sources/campus_water_completed1026_管长_铸铁DN200.net`。重建四区边界需要 Python 的 `shapely>=2.0` 和 Node.js，分区规则及几何校验在 `tools/campus_dma_20261027.py`；直接打开系统不需要这些构建依赖。`tools/read_epanet_net.py`读取完整Delphi值流并校验字节消耗与结束标记；源文件SHA256保存在provenance。原旧INP/DBF导入脚本 `tools/build-campus-dataset.py`仅用于重现历史版本，运行会把当前数据重新生成为旧版本。

页面使用等比例展示坐标，保留原测绘局部坐标；CRS未知，不叠加猜测底图。同编号同坐标的旧测绘地面高程/埋深可追溯保留，不能据此代替现场复核。当前未执行水力计算，未接入真实监测数据。

安装图册：[上海学校二级表安装定位图册（7页A3）](docs/installation/上海学校_二级表安装定位图册_20261026.pdf)，包含10处标注、局部放大图和现场确认表。标注数量不等于确认安装台数，北侧待选点与管段40的段内安装位置需现场确认。

PDF重建脚本为 `python tools/print-campus-installation.py`，直接读取仓库中的原始NET；需要 Python 的 `reportlab` 包及 Windows 微软雅黑字体。脚本输出覆盖仓库内同名图册，仅查看图册无需这些依赖。

## 数据与版本

城市主干管网内置数据为 137 点、167 条管线、4 个 DMA；原简版历史快照为 23 点、22 条管线、2 个 DMA。实际数量随用户编辑和导入变化。

顶部选择器切换查看版本。历史快照只读，当前版本的编辑不会覆盖历史快照。基于已有拓扑创建副本时复制已保存对象、DMA 及挂接规则，设备档案不重复创建。

地图使用已保存拓扑；编辑草稿不进入其他一张图。挂接规则保存后形成独立聚合监测点，固定样例监测点仍保留。所有采样和运行指标均未接通现场 SCADA。

## 监测历史趋势

从地图监测点详情或 SCADA 页面点击“查看完整趋势”，进入对应监测点的历史页。支持选择监测点、挂接设备、指标和起止时间，以及近 24 小时、3 天、7 天快捷查询；默认显示该对象最新可用采样之前的 24 小时，时间统一为北京时间。

杭州示例设备与内置监测点提供七天小时级示例采样，初始化后保存在本地，不覆盖已有历史。导入的真实源数据和手工新建设备不会自动编造历史记录。曲线、统计、分页明细及 XLSX 导出使用相同查询结果；缺测保留断点，无数据时间段显示空状态。多设备聚合按相同采样时刻及有效质量码计算，阀门等状态指标以明细展示。

本功能仍使用原型示例及浏览器本地数据，未接入实际 SCADA 历史服务。

## 功能边界

当前导入导出为拓扑和 DMA 的 JSON 格式，不支持 CAD/GIS 文件解析。设备协议字段仅用于登记，设备和挂接尚无独立导入导出。拓扑对比按两个版本已保存快照计算对象差异；监测趋势无历史序列时显示空状态。报警、工单与巡检支持本地保存和执行闭环，报警源与班组动作仍为模拟；到期工单需手动生成，尚无后台调度、真实派送或现场证据。详见[报警工单巡检检查与落地说明](../1.%20设计资料包/报警工单巡检检查与落地说明_20260915.md)。

拓扑管理菜单顺序为拓扑版本管理、拓扑编辑器、拓扑设备管理。项目及菜单入口默认读取“使用中”版本；版本行的编辑、设备配置、对比和导出使用对应版本。详细核查范围见设计资料包《拓扑版本一致性检查记录_20260914.md》。

尚未提供生产级认证授权、发布审批、多用户协同、服务端备份、审计及真实时序归档。详细限制见产品说明书第 12—14 节。

历史改动记录见 [CHANGELOG](CHANGELOG.md)，历史记录用于追溯，不替代当前产品说明书。

报警与工单页面采用地图主视图，左侧记录筛选、地图标记和右侧处理详情联动。巡检管理仅展示任务列表及配置；到期派发入口位于工单地图的“巡检任务派发”。

## DMA 分区计量与漏损分析（2026-10-23）

- DMA 一张图围绕分区用水量、平均压力、营收水量展示。分区用水量为同期进口累计水量减出口累计水量（m³），不扣储水变化；平均压力取区内有效压力监测设备数据（MPa），与月水量分别标明时间口径。
- 分区名称在概览首位编辑；颜色在 DMA 分区面图层配置中保存；地图左上角图层右侧可选择统计月份。计量明细不重复概览字段。分区 ID 由系统设置、只读。设备数按已挂接设备去重，缺测和未接入设备不会生成水量或压力结果。
- “DMA 漏损分析”提供月度水量对比（用水量与营收水量双曲线）、月度差值、小时用水量三个视图。“查看明细”打开对应粒度表格，月度可进一步查看日用水量；导出使用当前查询范围和粒度。
- 每小时水量使用该小时所有进口减所有出口的累计量；瞬时流量 m³/h 不直接作为水量。月营收取区内用户水表同月期末减期初读数后汇总，支持独立月营收记录；不生成小时/每日营收和差值。
- 月差值 = 月分区用水量 − 月营收水量。缺数、重复、质量异常、未抄齐或跨月账期不直接相减；负差值保留并提示核对，不认定物理漏水。
- 支持补录日进出水量和已核算月营收用量。日补录不推算小时曲线。杭州示例按小时模拟进出水量并汇总到日/月，营收单独按月提供；上海学校项目补齐五分区展示样例，并标注“演示数据”；原始导入数据保持未接入真实监测。
- 统计模块兼容旧扩展水量平衡 API；储水变化、未收费合法用水等不再混入主指标。真实设备和营销接口仍需后端接入，当前为浏览器本地原型。
- 浏览器验证：`node tools/verify-dma-core.cjs`（启动本目录 HTTP 服务至 127.0.0.1:8765）。`verify-dma-monthly.cjs` 保留为相同验证入口。
